# Overview
The repository includes the finished dashboard code and the README from Project Two, as well as the CRUD Python module I wrote in Project One. These artifacts showcase my aptitude for creating maintainable, adaptable software solutions for database work and for building intuitive dashboards.
# Reflecting on Maintainable, Readable, and Adaptable Programming
In writing applications, I value code structure and uniformity, sensible design with meaningful variable and function names, modular development, and thorough code documentation. To illustrate, the CRUD Python module abstracts database processing using well-defined functions that handle creating, reading, updating, and deleting records. This abstraction allows us to better interact with the database widgets in the dashboard I’ve created in Project Two. 
# Applying a CRUD module has several benefits:  
 • Reusability: A module can be used in similar database interaction projects and can be used in other projects using the same module.  
 • Maintainability: All changes to the database logic need to be updated in one place.  
 • Readability: Dashboard code is cleaner and more obvious if it calls simple CRUD functions instead of raw SQL queries.
I could develop and add other features like transaction management, connection pooling, or adapt it for other database systems to meet new project requirements.  
# How to Solve Problems as a Computer Scientist 
In terms of meeting the requirements of the client, I have an idea of what a client should have to implement Grazioso Salvare’s database and dashboard. I first had to learn about the problem context and the data needed for the project. I took what I learned and broke down the project into pieces that I could manage: a design of data schema, backend CRUD operations, and frontend dashboard integration. Unlike previous assignments, which were more separate or theoretical, this was a structured way to approach it. This experience created a real-life simulation of the interaction of components in a project to provide a complete solution.
# Going forward, I would:
Discuss with the clients and get detailed requirements before their implementation. It will make sense to iterate and test to check functionality, so when the testing is complete, one will know if it works. Normalize databases and optimize query design to improve performance.
